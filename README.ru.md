# Установка

1. Скачай `Metamorph-Creative-Menu.zip` по ссылке выше.
2. Запусти Noita и открой **Mods** в главном меню.
3. Нажми **Open mods folder**.
4. Распакуй или перемести папку `metamorph_creative_menu` в открывшуюся папку `mods`. Итоговый путь должен напрямую содержать `metamorph_creative_menu/mod.xml`, без лишней вложенной папки от архива.
5. Если старая копия уже установлена, замени папку `metamorph_creative_menu` целиком, а не объединяй старые и новые файлы.
6. Вернись в Noita и обнови список модов.
7. Разреши **Unsafe Mods**.
8. Включи **Metamorph: Creative Menu** и начни игру с активными модами.

Не включай standalone-сборку с GitHub и Steam Workshop-версию одновременно.

# Standalone-сборка и Steam Workshop

Сборка, распространяемая через этот GitHub-репозиторий, является полной standalone-сборкой. Она включает NoitaPatcher и функции, которым нужен неограниченный mod API, в том числе низкоуровневую работу с материалами и нативное восстановление после Game Over.

[Steam Workshop-сборка](https://steamcommunity.com/sharedfiles/filedetails/?id=3785170245) устанавливается отдельно. В ней нет нативных компонентов, необходимых для функций, доступных только в standalone-сборке.

Обе сборки используют один и тот же идентификатор мода, поэтому одновременная установка может привести к дублированию или конфликту файлов и не поддерживается.

# О моде

**Metamorph: Creative Menu (MCM)** — креативное меню и sandbox-набор для Noita.

В одном интерфейсе собраны инструменты для:

- заклинаний и инвентаря заклинаний;
- редактирования жезлов и переиспользуемых пресетов;
- предметов и ёмкостей с жидкостями;
- полного каталога материалов и рисования материалами;
- перков и поддерживаемого удаления перков;
- статусов и GameEffect-сущностей;
- существ, превращений и вселения;
- погоды и времени;
- глобальных правил мира;
- телепортации;
- опциональной интеграции с Entangled Worlds;
- восстановления после превращения, смерти формы и Game Over.

MCM старается работать с настоящим состоянием Noita, а не заменять всё декоративными копиями. Существующие карточки заклинаний перемещаются как сущности, выдача предметов учитывает структуру инвентаря, изменения жезла проходят через commit/rollback, материалы остаются настоящими симулируемыми материалами, а обратимые правила мира сохраняют достаточно исходного состояния, чтобы поддерживаемые параметры можно было вернуть.

Entangled Worlds не обязателен. Без него MCM остаётся полноценным одиночным модом.

# Управление

Стандартные клавиши:

| Действие | По умолчанию |
| --- | --- |
| Открыть / закрыть креативное меню | **F4** |
| Вернуться в человеческую форму во время превращения | **TAB** |
| Вселиться в существо в мире | **G** |
| Рисовать выбранным материалом | **Средняя кнопка мыши** |

Панель MCM также доступна через обычный интерфейс инвентаря Noita.

Назначения можно менять в разделе **CONTROLS** и в настройках мода Noita. Поддерживаются клавиши, кнопки мыши и точные комбинации с **CTRL / SHIFT / ALT**.

Во время назначения:

- **DELETE / BACKSPACE** очищает привязку;
- **ESC** отменяет ввод;
- **R** возвращает стандартную клавишу для выбранного действия;
- **RESET ALL** после подтверждения восстанавливает все стандартные привязки.

Одинаковые привязки можно оставить, но MCM показывает конфликт вместо тихой замены другого действия.

Можно переназначить действия навигации меню, открытия разделов, возврата из формы, вселения, рисования материалами, очистки эффектов, освобождения погоды, сброса правил мира и поддерживаемые мультиплеерные действия.

# Окно Creative Menu

Отдельная панель MCM — это сохраняемое изменяемое окно, а не фиксированный debug-overlay.

Его можно:

- перемещать за заголовок;
- растягивать за края и углы;
- сворачивать;
- закрывать;
- возвращать к стандартной раскладке.

Положение, ширина, высота и последний открытый раздел сохраняются между запусками. После изменения разрешения сохранённая геометрия подгоняется так, чтобы окно оставалось в видимой области GUI.

Списки и каталоги используют измеряемые раскладки и scroll-контейнеры Noita. При изменении размеров сразу меняется объём видимого содержимого, а переведённые подписи могут переноситься на несколько строк без наложения на соседние элементы. На узком окне элементы переходят на новые строки вместо того, чтобы рисоваться поверх друг друга.

Само открытие или наведение на отдельное окно не должно надолго отключать управление игроком. Когда клик, перетаскивание или активное текстовое поле могли бы одновременно сработать и в игре, MCM временно подавляет нужное управление игроком и затем восстанавливает его.

# Поиск и локализация

Поиск доступен в основных каталогах, включая заклинания, предметы, материалы, перки и существ.

В зависимости от записи поиск умеет учитывать:

- название на текущем языке интерфейса;
- английское название;
- ключ локализации;
- технический идентификатор;
- XML-путь.

Поиск не зависит от регистра, нормализует распространённые диакритические знаки и разделители и допускает небольшие опечатки в длинных запросах.

Собственный интерфейс MCM локализован на:

- английский;
- русский;
- бразильский португальский;
- испанский;
- немецкий;
- французский;
- итальянский;
- польский;
- упрощённый китайский;
- японский;
- корейский.

Для обычного контента Noita мод по возможности использует локализационные ключи самой игры вместо поддержки отдельного дубликата названий.

# Заклинания

Раздел заклинаний работает и с каталогом, и с уже существующими сущностями заклинаний игрока.

Основная рабочая область показывает:

- обычные слоты активного жезла;
- карточки **ALWAYS CAST**;
- инвентарь заклинаний игрока;
- поисковый каталог заклинаний.

## Быстрая замена выбранного слота

Короткий клик выбирает слот жезла. После этого короткий LMB по заклинанию из каталога заменяет выбранный слот.

Это быстрый режим обычного редактирования. Для точного перемещения используется drag-and-drop.

## Транзакционный drag-and-drop

Существующие карточки можно перетаскивать:

- между слотами жезла;
- из обычных слотов в **ALWAYS CAST**;
- из **ALWAYS CAST** обратно в обычные слоты;
- в конкретный слот инвентаря заклинаний;
- из инвентаря обратно на жезл;
- в игровой мир;
- в корзину, где это поддерживается.

Для уже существующей карточки MCM по возможности перемещает реальную сущность. Поэтому изменённое состояние карты, оставшиеся использования и данные, добавленные другими модами, не теряются просто из-за смены позиции.

Источник остаётся неизменным, пока транзакция назначения не подтверждена. Неверная или неизвестная цель отменяет операцию, а не удаляет исходную карточку. Один отпуск мыши выполняет максимум одну подтверждённую операцию.

Карточки каталога — это шаблоны и никогда не расходуются при перетаскивании.

## Always Cast

У Always Cast есть отдельная полоса. Повышение, понижение и обмен учитывают эффективную ёмкость обычных слотов жезла, чтобы не получить некорректную структуру.

## Отмена и повтор

Для внутренних изменений жезла есть ограниченная история **UNDO / REDO**.

Операции, которые передают реальную сущность во внешний мир или другой инвентарь, не всегда можно безопасно отменить по одному снимку жезла, поэтому такие внешние передачи не обещаются как универсально обратимые.

# Жезлы

Рабочая область жезла редактирует жезл, который игрок держит в руках.

Поддерживаемые параметры:

- ёмкость / количество слотов;
- заклинаний за выстрел;
- время перезарядки;
- задержка между выстрелами;
- разброс;
- множитель скорости снарядов;
- максимальная мана;
- скорость восстановления маны;
- восстановление отдачи;
- уровень жезла;
- shuffle;
- режим без перезарядки.

MCM также редактирует внешний вид и связанные метаданные:

- отображаемое имя;
- блокировки жезла и карточек;
- путь к спрайту;
- смещения спрайта;
- точку выстрела.

Визуальный каталог внешнего вида по возможности следует данным из XML жезлов.

## Пресеты жезлов

Жезл можно сохранить как именованный постоянный пресет и использовать в следующих мирах и последующих запусках Noita.

Пресет может сохранять:

- характеристики жезла;
- значения маны;
- визуальные метаданные;
- обычные карточки заклинаний;
- Always Cast;
- позиции карточек по слотам;
- оставшиеся использования;
- замороженное состояние карточек.

У каждого пресета две отдельные операции:

- **APPLY** записывает сохранённый blueprint в жезл, который сейчас держит игрок;
- **GET COPY** создаёт новый жезл из того же blueprint.

Копия помещается в свободный слот жезла в быстром инвентаре, если он есть. Если подходящего слота нет, полностью собранный жезл остаётся в мире рядом с игроком.

Замена жезла и загрузка пресета используют commit/rollback. Если создание или размещение не удаётся завершить, MCM старается удалить неполное дерево сущностей, а не оставлять сломанный частичный жезл.

# Предметы и жидкости

## Предметы

Короткий **LMB** по записи каталога создаёт один поддерживаемый предмет рядом с игроком.

**RMB** пытается поместить предмет в подходящую область инвентаря.

Запись каталога также можно перетащить:

- на подходящую цель в быстром инвентаре;
- за пределы меню в точную позицию игрового мира.

Если отпустить карточку внутри меню без корректной цели, операция отменяется. Сама карточка каталога — только шаблон и никуда не исчезает.

MCM учитывает обычное разделение быстрого инвентаря Noita на слоты жезлов и предметов. При неудачной загрузке XML, заполнении жидкостью, передаче в инвентарь или опциональной мультиплеерной передаче новая сущность по возможности удаляется.

Некоторые настоящие инвентарные предметы физически лежат в игровых каталогах, ориентированных на существ. MCM классифицирует известные случаи по поведению и не считает имя папки единственным источником истины о том, предмет это или существо.

## Жидкости

Записи жидкостей создают настоящие заполненные контейнеры Noita, а не декоративные объекты интерфейса.

Такой контейнер можно носить, бросать, разбивать и разливать, а содержимое участвует в обычных реакциях материалов.

# Материалы

Раздел материалов — инструмент рисования миром на основе реального реестра материалов Noita.

Каталог собирается из зарегистрированных движком жидкостей, песков / порошков, газов, огня, твёрдых и связанных статических или particle-effect материалов. Поэтому корректно зарегистрированные материалы других активных модов могут появляться автоматически.

Поиск материалов и дорогая валидация распределяются на ограниченные порции работы вместо сканирования всего каталога в одном UI-кадре.

## Отображение материалов

Жидкости используют то же отображение заполненного контейнера, что и раздел предметов.

Для остальных материалов MCM предпочитает авторские текстуры и tint-данные из `materials.xml`, включая унаследованные определения. Если авторской текстуры нет, fallback строится из реального цвета материала в движке, а не из случайного preview-цвета.

## Рисование

1. Выбери материал.
2. Выбери размер кисти.
3. Включи режим рисования.
4. Закрой инвентарь.
5. Удерживай назначенную кнопку рисования в игровом мире.

Открытие инвентаря выключает активный режим рисования.

Рисование не создаёт просто декоративные частицы. MCM помещает реальные клетки в мир подходящим для движка способом. Динамические материалы продолжают жить по правилам Noita: жидкости текут, порошки осыпаются, газы двигаются, огонь реагирует, а нестабильные вещества могут превращаться через реакции материалов.

Разным классам материалов нужны разные методы размещения. Standalone-сборка может использовать прямой доступ NoitaPatcher к сетке мира и небольшой PixelScene-fallback для авторских случаев, когда Noita не позволяет напрямую создать клетку в конкретной координате текстуры.

Очереди ограничены, чтобы большая кисть не выполняла намеренно неограниченный объём работы за один кадр.

# Перки

## Создание и получение перков

**LMB** создаёт обычный pickup выбранного перка в мире.

Действие получения умеет выдавать выбранный перк единично или пачкой. Массовые операции обрабатываются как bounded jobs, а не применяют все копии в одном UI-кадре.

Интерфейс показывает прогресс, а ещё не выполненную работу можно отменить. Копии, уже подтверждённые до отмены, остаются на игроке.

Каждая выданная копия всё равно проходит через обычный путь применения перка вместо прямой подделки конечного состояния.

## Удаление перков

Удалить перк значительно сложнее, чем выдать его. Перки могут менять globals, компоненты, сущности, характеристики игрока и долгоживущие игровые механики, а универсальной обратной операции в Noita нет.

Поэтому MCM удаляет только состояние, для которого есть достаточно безопасная отслеживаемая обратная операция. Журнал транзакции старается убрать только состояние, принадлежащее конкретному применению перка, не сбрасывая постороннее состояние игрока.

Если очистка выполнена частично или её нельзя доказуемо завершить, она остаётся отмеченной как незавершённая, а не молча объявляется успешной.

Сторонний перк может выдаваться, но это не гарантирует, что его можно корректно удалить.

# Эффекты

Раздел эффектов применяет и снимает поддерживаемые material-status и GameEffect-сущности.

Удаление по возможности учитывает владельца состояния. MCM не пытается без разбора уничтожать похожие скрытые эффекты, которые принадлежат перкам, игре или другой системе.

Постоянные эффекты, созданные MCM, используют ограниченную очистку / expiry-обработку, чтобы удаление одного MCM-эффекта не сбрасывало постороннее состояние.

# Существа

Каталог существ сохраняет точные XML-пути и не объединяет все сущности с похожими именами.

Поддерживаемые действия:

- **LMB** — создать выбранную авторскую сущность рядом с игроком;
- перетянуть за пределы меню — создать её в подтверждённой позиции мирового курсора;
- **RMB** — превратить текущего игрока в поддерживаемую форму;
- специальная запись **PLAYER** — создать или восстановить player-состояние, как описано ниже.

Если вернуть перетаскиваемую карточку над меню, создание в мире отменяется.

Правила совместимости для опасных или необычных форм задаются точными путями. Имя файла, в котором просто встречается знакомое слово, не делает сущность автоматически эквивалентной другой форме.

# Превращения и возврат в человека

Игровые формы по возможности сохраняют полезное нативное движение, атаки, внешний вид и физику. Компоненты, которые напрямую конкурируют с вводом игрока, могут временно отключаться или адаптироваться, пока форма управляется игроком.

Некоторым сложным существам нужна дополнительная совместимость. Боссы, скриптовые оболочки и тяжёлые физические сущности не обязаны вести себя абсолютно так же, как их оригинальные AI-версии, когда ими управляет игрок.

Назначенное действие возврата — **TAB по умолчанию** — сначала использует обычный путь завершения превращения. Если этого недостаточно, standalone-сборка использует дополнительные пути восстановления через NoitaPatcher.

В поддерживаемых случаях смертельного урона MCM пытается:

- оставить умершую временную форму или труп в мире, когда это уместно;
- восстановить человеческую сущность игрока;
- вернуть authority и управление;
- сохранить инвентарь;
- восстановить релевантное состояние игрока.

Это механизм восстановления, а не абсолютное бессмертие. Сторонний kill-script, несовместимое состояние движка или падение процесса могут обойти поддерживаемую передачу.

# Вселение

Вселение позволяет управлять существом, уже существующим в мире, вместо выбора формы из каталога.

Клавиша по умолчанию — **G**.

Наведи курсор на подходящее существо и используй действие вселения. MCM проверяет цель, готовит совместимый переход формы и удаляет или переводит исходную мировую сущность в неактивное состояние только после подтверждения нового управляемого состояния.

Если переход не удался, исходное существо не должно просто исчезнуть.

Вселение не ограничено встроенным каталогом MCM. Совместимое существо из другого мода тоже может работать, но универсальная поддержка всех сторонних сущностей не гарантируется.

# Запись Player

**PLAYER** — специальная запись каталога существ, а не обычная polymorph-форма.

Действие создания создаёт отдельного player-подобного персонажа и пытается скопировать подходящие визуальные данные и максимальное здоровье игрока.

Использование действия превращения на **PLAYER** не превращает уже человеческого игрока в дубликат. Если игрок находится в другой форме, действие используется как возврат в человека.

# Восстановление после Game Over в одиночной игре

Standalone-сборка для одиночной игры добавляет дополнительный путь восстановления в стандартный экран Game Over Noita.

Когда нативная интеграция может безопасно найти необходимые структуры игры, MCM добавляет в интерфейс Game Over действие **«I didn't die»**.

Во время игры MCM поддерживает актуальную резервную копию player-состояния. Нажатие восстановления отправляет запрос через обычный update-путь MCM, а не пытается перестроить всего игрока прямо из обработчика кнопки интерфейса.

Поддерживаемое восстановление пытается:

- восстановить или получить живую сущность игрока;
- снова сделать её authoritative;
- убрать Game Over-состояние движка;
- вернуть управление и пригодное состояние игрока;
- по возможности очистить Game Over audio, music и UI-состояние;
- дать короткое окно защиты после восстановления.

Нативный helper работает fail-closed. Он сканирует запущенный поддерживаемый executable Noita в поиске известных структур вместо записи по одному навсегда зашитому адресу. Если после обновления игры нужные структуры нельзя безопасно определить, опциональное восстановление не используется вместо записи в неизвестное место.

# Погода и время

MCM умеет управлять поддерживаемым состоянием погоды и времени, включая пресеты и отдельные параметры, доступные в текущей реализации.

Принудительное состояние затем можно освободить обратно под управление игры. Например, после фиксации времени суток MCM может перестать владеть параметром, и естественное течение времени Noita продолжится.

Изменения погоды рассматриваются как управляемое состояние, а не как одноразовые консольные команды.

# Правила мира

Раздел **RULES** изменяет поддерживаемое глобальное поведение игры.

Правила затрагивают, например:

- отношения существ;
- поведение золота;
- использование заклинаний;
- fog of war;
- отдельные награды за убийства;
- выпадение лечения;
- поведение крови;
- гравитацию;
- физику;
- силу пинка;
- physics joints;
- цикл дня и ночи;
- другие поддерживаемые глобальные параметры.

Главная цель — обратимость.

Для поддерживаемых правил MCM сохраняет или вычисляет исходное состояние, чтобы затем вернуть настройку. Множители применяются относительно исходного значения, а не повторно умножают уже изменённый результат.

Правила, которым нужно затронуть много сущностей или физических объектов, используют ограниченную по кадрам работу вместо попытки синхронно переписать весь мир одним кликом.

# Телепортация

Раздел телепортации содержит подготовленные точки по миру, включая места на основном маршруте, Holy Mountains, крупные боковые области и другие поддерживаемые ориентиры.

Перед перемещением MCM может запросить загрузку нужной области и ищет ближайшее пригодное свободное место вместо намеренного помещения игрока прямо внутрь твёрдой стены.

Телепортация всё равно зависит от способности мира загрузить и предоставить корректную точку. Сильно изменённые миры могут потребовать fallback-поведения.

# Entangled Worlds

**Entangled Worlds / Noita Proxy опционален.** MCM работает без него.

Если EW присутствует, MCM включает дополнительное multiplayer-aware поведение. Для MCM-специфичного синхронизируемого состояния всем участникам рекомендуется использовать совместимые сборки MCM.

## Authority и формы

Формам игрока нужна особая обработка владения, потому что превращённый игрок не должен случайно оставлять вторую сетевую authority.

MCM координирует с EW владение формой, retirement и возврат к человеку там, где это поддерживается. Для boss/Kolmi-подобных сущностей есть дополнительный lifecycle-код, предназначенный для предотвращения дублированных authority и старых сетевых копий.

Обычный death-путь EW остаётся главным для сущностей, которые не распознаны как MCM-owned form state.

## Предметы, жезлы и заклинания

Где возможно, MCM использует штатные механизмы предметов / инвентаря EW вместо отдельной параллельной транспортной системы.

После подтверждённых изменений жезлов и инвентаря заклинаний запрашивается соответствующее мультиплеерное обновление, если интеграция доступна. Предметы, созданные MCM в мире, могут передаваться через стандартный EW world-item путь.

## Перки

Обычные pickup-перки могут использовать штатную синхронизацию world items EW. Собственная обработка perk-state в MCM координирует refresh и bounded operations так, чтобы массовое действие не пыталось выполнять дорогое глобальное обновление после каждой отдельной копии.

## Материалы

Для рисования материалами нужен отдельный путь совместимости, потому что изменения клеток мира не являются обычными item entities.

MCM держит paint-work ограниченным, разделяет работу по границам chunk и выполняет необходимые EW world-frame / persistence шаги перед выпуском синхронизируемой conversion-работы. Незагруженный streaming-edge chunk откладывается, а не блокирует весь текущий штрих.

Цель — чтобы ближайшие EW-участники видели поддерживаемое нарисованное состояние мира без удалённого повторения обычного UI-действия MCM в виде filename-only PixelScene RPC.

При этом сохраняются ограничения EW по material id: принимающая игра не может корректно создать материал, которого у неё нет или чей реестр материалов движка несовместим.

## Погода, вселение и состояние мира

Поддерживаемое мультиплеерное состояние MCM также включает координацию погоды, вселения и отдельных правил мира / lifecycle-состояния. Проверки authority нужны, чтобы два участника не пытались одновременно стать владельцами одного состояния.

Поддержка EW намеренно консервативна. Если интеграция не может доказать безопасный путь синхронизации, MCM предпочитает корректное локальное поведение вместо притворной поддержки любой одиночной операции в мультиплеере.

# Совместимость и ограничения

Noita предоставляет многие системы через слабо связанные сущности, XML, Lua-компоненты и нативное поведение движка. Поэтому MCM не может гарантировать универсальную совместимость со всеми модифицированными сущностями или будущими обновлениями игры.

Важные ограничения:

- возможность создать существо не означает, что оно безопасно как player-form;
- возможность выдать перк не означает наличие надёжной обратной операции;
- внешнюю передачу заклинания или предмета не всегда можно отменить по внутреннему снимку;
- сторонние скрипты могут обходить поддерживаемые пути смерти и восстановления;
- нативное восстановление зависит от поддерживаемого поведения executable Noita и отключается fail-closed, если нужные структуры нельзя определить;
- Entangled Worlds не может синхронизировать материал, отсутствующий в реестре принимающей игры;
- сильно изменённые инвентари, сущности или правила мира могут потребовать отдельной совместимости с конкретным модом.

MCM старается сохранять исходное состояние и откатывать неудачные изменения, но sandbox-инструмент, меняющий живое состояние игры, не способен сделать каждую комбинацию сторонних модов полностью транзакционной.

# Сохраняемые данные

MCM сохраняет пользовательское состояние, которое должно переживать перезапуски: поддерживаемые настройки, клавиши, раскладку меню и пресеты жезлов.

Идентификатор мода остаётся стабильным, поэтому нормальное обновление сохраняет поддерживаемые данные. При установке новой standalone-сборки всё равно рекомендуется заменять папку мода целиком, потому что слияние старых и новых файлов может оставить устаревшие runtime-файлы.

# Решение проблем

## Мод не появляется

Проверь, что структура заканчивается так:

`mods/metamorph_creative_menu/mod.xml`

Лишняя папка архива над `metamorph_creative_menu` мешает Noita корректно увидеть мод.

## Не работают нативные функции или материалы

Убедись, что разрешены **Unsafe Mods** и установлена standalone-сборка с GitHub, а не смесь GitHub- и Workshop-файлов.

## Меню открывается, но одновременно срабатывает игровое действие

Проверь пользовательские привязки на конфликты. MCM показывает дубликаты, но намеренно позволяет оставить их, если это нужно.

## В существо нельзя безопасно превратиться

Не каждая создаваемая XML-сущность является поддерживаемой player-form. Для существ со специальными требованиями используются правила по точному пути.

## Перк нельзя удалить

Удаление доступно только там, где у MCM есть поддерживаемая обратная операция для отслеживаемого состояния. Это намеренное ограничение: угадывание очистки может повредить несвязанное состояние игрока.

## В мультиплеере поведение отличается у участников

Используй совместимые сборки MCM на всех участниках и совместимую среду Noita / Entangled Worlds. MCM не может исправить несовместимый material registry или произвольные сетевые изменения других модов.

# Сообщение об ошибках

Полезный баг-репорт содержит:

- что именно ты пытался сделать;
- точный раздел и действие MCM;
- воспроизводится ли проблема в одиночной игре, Entangled Worlds или в обоих режимах;
- установлена ли standalone- или Workshop-сборка;
- активны ли другие gameplay-моды;
- надёжные шаги воспроизведения;
- релевантные логи Noita / EW, если они доступны.

Для проблем с превращением, вселением, предметом или материалом по возможности укажи точную сущность или материал. Технический идентификатор часто полезнее переведённого отображаемого имени.

# Репозиторий и исходники разработки

Репозиторий намеренно содержит **полное дерево разработки**, а не тот же урезанный архив, который скачивают игроки.

`metamorph_creative_menu/` содержит runtime-код вместе с:

- автоматическими тестами;
- QA-инструментами;
- диагностикой;
- нативными исходниками;
- build-инструментами;
- правилами очистки релиза;
- документацией для разработки.

Эти файлы нужны для разработки и регрессионного тестирования, поэтому остаются в GitHub source. Готовый player ZIP создаётся отдельно и исключает development-only содержимое.

Player-сборка также получает release-only очистку, включая минимальный player `README.txt`, тогда как source-tree сохраняет нормальную документацию разработки.

# Тесты

Автоматический набор тестов находится в `metamorph_creative_menu/tests/` и сочетает Python contract-checks с Lua mock-тестами.

Из корня репозитория release workflow прогоняет тесты по полному импортированному source перед публикацией player build. Для Lua mock-части требуется `texlua`.

Source hygiene также защищает production-файлы и документацию от мусора истории разработки, устаревших debug-интерфейсов и случайных process-artifacts.

# Импорт исходного архива и выпуск сборки

Полный development source можно импортировать из архива семейства `Metamorph-Creative-Menu-v...zip`.

Import workflow проверяет структуру архива, требует полный набор компонентов разработки, запускает source hygiene и регрессионные тесты до коммита импортированного дерева.

ModWorkshop / player-style архив не считается development source.

Публичный `latest-build` затем создаётся из полного source отдельным player-builder. Он удаляет QA, тесты, диагностику, native source и прочий development-only payload, применяет release cleanup, валидирует итоговый архив и только после этого обновляет стабильный download asset.

Такое разделение позволяет репозиторию оставаться полноценной базой разработки, а обычной загрузке для игрока — быть компактной и без development-инструментации.

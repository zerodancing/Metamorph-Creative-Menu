GitHub release는 전체 개발 소스 트리에서 자동으로 생성됩니다. 테스트, QA 도구, 진단 코드, 네이티브 소스 및 빌드 도구는 저장소에 남지만 플레이어용 아카이브에는 포함되지 않습니다.

GitHub standalone 빌드에는 NoitaPatcher와 네이티브 복구 기능이 포함되므로 **Unsafe Mods를 허용**해야 합니다.

# 설치

1. 위 링크에서 `Metamorph-Creative-Menu.zip`을 다운로드합니다.
2. Noita를 실행하고 메인 메뉴에서 **Mods**를 엽니다.
3. **Open mods folder**를 누릅니다.
4. `metamorph_creative_menu` 폴더를 `mods` 폴더에 압축 해제하거나 이동합니다. 최종 경로는 추가 압축 폴더 없이 바로 `metamorph_creative_menu/mod.xml`을 포함해야 합니다.
5. 이전 사본이 있다면 오래된 파일과 새 파일을 합치지 말고 `metamorph_creative_menu` 폴더 전체를 교체하세요.
6. Noita로 돌아가 모드 목록을 새로고침합니다.
7. **Unsafe Mods**를 허용합니다.
8. **Metamorph: Creative Menu**를 활성화하고 모드를 켠 상태로 게임을 시작합니다.

GitHub standalone 빌드와 Steam Workshop 빌드를 동시에 활성화하지 마세요.

# Standalone 빌드와 Steam Workshop

이 GitHub 저장소에서 배포되는 빌드는 완전한 standalone 빌드입니다. NoitaPatcher와 제한 없는 mod API 접근이 필요한 기능을 포함하며, 저수준 재료 조작 및 Game Over 이후 네이티브 복구 기능도 포함됩니다.

[Steam Workshop 빌드](https://steamcommunity.com/sharedfiles/filedetails/?id=3785170245)는 별도로 설치됩니다. Standalone 전용 기능에 필요한 네이티브 구성 요소는 포함하지 않습니다.

두 빌드는 같은 모드 ID를 사용합니다. 동시에 설치하면 파일 중복이나 충돌이 생길 수 있으며 지원되지 않습니다.

# 모드 소개

**Metamorph: Creative Menu (MCM)**은 Noita용 크리에이티브 메뉴이자 샌드박스 툴킷입니다.

다음 기능을 하나의 인터페이스에 모읍니다.

- 주문 및 주문 인벤토리
- 완드 편집 및 재사용 가능한 완드 프리셋
- 아이템 및 액체 용기
- 전체 재료 카탈로그와 재료 페인팅
- 퍽 및 지원되는 퍽 제거
- 상태 효과 및 GameEffect 엔티티
- 생물, 변신 및 빙의
- 날씨와 시간
- 전역 월드 규칙
- 순간이동
- 선택적 Entangled Worlds 연동
- 변신, 폼 사망 및 Game Over 이후 복구 경로

MCM은 가능한 한 장식용 복사본으로 대체하지 않고 Noita의 실제 상태를 직접 다룹니다. 기존 주문 카드는 실제 엔티티로 이동하고, 아이템 전달은 인벤토리 구조를 존중하며, 완드 변경은 commit/rollback 경로를 사용하고, 재료는 실제 시뮬레이션 대상 재료로 유지됩니다. 또한 되돌릴 수 있는 월드 규칙은 나중에 복원할 수 있도록 충분한 원래 상태를 보존합니다.

Entangled Worlds는 선택 사항입니다. 없어도 MCM은 완전한 싱글플레이 모드로 동작합니다.

# 조작

기본 입력:

| 동작 | 기본 입력 |
| --- | --- |
| 크리에이티브 메뉴 열기 / 닫기 | **F4** |
| 변신 중 인간 형태로 복귀 | **TAB** |
| 월드의 생물에 빙의 | **G** |
| 선택한 재료로 그리기 | **마우스 가운데 버튼** |

크리에이티브 패널은 Noita의 일반 인벤토리 인터페이스에서도 사용할 수 있습니다.

키 바인딩은 MCM의 **CONTROLS** 섹션과 Noita 모드 설정에서 바꿀 수 있습니다. 키보드 키, 마우스 버튼, 정확한 **CTRL / SHIFT / ALT** 조합을 지원합니다.

키를 지정하는 동안:

- **DELETE / BACKSPACE** — 바인딩 삭제
- **ESC** — 취소
- **R** — 해당 동작의 기본값 복원
- **RESET ALL** — 확인 후 모든 기본 바인딩 복원

중복 바인딩은 그대로 둘 수 있지만, MCM은 다른 동작을 조용히 덮어쓰지 않고 충돌을 표시합니다.

메뉴 이동, 섹션 전환, 폼 복귀, 빙의, 재료 페인팅, 효과 정리, 날씨 제어 해제, 월드 규칙 초기화 및 지원되는 멀티플레이 동작을 재지정할 수 있습니다.

# Creative Menu 창

직접 여는 크리에이티브 패널은 고정 debug overlay가 아니라 상태가 저장되는 크기 조절 가능 창입니다.

다음이 가능합니다.

- 제목 부분을 잡고 이동
- 가장자리와 모서리에서 크기 조절
- 최소화
- 닫기
- 기본 레이아웃으로 복원

위치, 너비, 높이, 마지막으로 연 섹션은 실행 사이에 저장됩니다. 해상도가 바뀌면 저장된 창 위치는 보이는 GUI 영역 안으로 다시 제한됩니다.

목록과 카탈로그는 측정된 레이아웃과 Noita 스크롤 컨테이너를 사용합니다. 창 크기를 바꾸면 보이는 콘텐츠 양도 즉시 바뀌고, 긴 번역 라벨은 다른 컨트롤을 덮지 않고 줄바꿈됩니다. 좁은 레이아웃에서는 컨트롤이 다음 줄로 재배치됩니다.

창을 열거나 마우스를 올리는 것만으로 게임 조작이 계속 비활성화되지는 않습니다. 클릭, 드래그, 텍스트 입력 포커스가 플레이어 입력과 충돌할 수 있는 경우에만 관련 입력을 잠시 막았다가 다시 복원합니다.

# 검색과 현지화

주문, 아이템, 재료, 퍽, 생물 등 주요 카탈로그에서 검색할 수 있습니다.

항목에 따라 다음 정보를 검색 대상으로 사용합니다.

- 현재 UI 언어 이름
- 영어 이름
- 현지화 키
- 기술 식별자
- XML 경로

검색은 대소문자를 구분하지 않고 일반적인 악센트와 구분자를 정규화하며, 긴 검색어의 작은 오타를 일부 허용합니다.

MCM 자체 인터페이스는 다음 언어를 지원합니다.

- 영어
- 러시아어
- 브라질 포르투갈어
- 스페인어
- 독일어
- 프랑스어
- 이탈리아어
- 폴란드어
- 중국어 간체
- 일본어
- 한국어

일반적인 Noita 콘텐츠는 가능하면 게임 자체의 현지화 키를 재사용하여 중복 이름 목록을 유지하지 않습니다.

# 주문

주문 섹션은 카탈로그뿐 아니라 플레이어가 실제로 가진 주문 엔티티도 다룹니다.

주 작업 영역에는 다음이 표시됩니다.

- 현재 완드의 일반 슬롯
- **ALWAYS CAST** 카드
- 플레이어 주문 인벤토리
- 검색 가능한 주문 카탈로그

## 선택 슬롯 빠른 교체

완드 슬롯을 짧게 클릭하면 선택됩니다. 이후 카탈로그 주문을 짧게 LMB 클릭하면 해당 슬롯을 교체합니다.

일반 편집을 위한 빠른 방식이며, 정확한 이동은 drag-and-drop을 사용합니다.

## 트랜잭션 방식 drag-and-drop

기존 카드는 다음 위치 사이에서 이동할 수 있습니다.

- 완드 슬롯 사이
- 일반 슬롯에서 **ALWAYS CAST**로
- **ALWAYS CAST**에서 일반 슬롯으로
- 주문 인벤토리의 특정 슬롯으로
- 인벤토리에서 완드로
- 게임 월드로
- 지원되는 경우 휴지통으로

기존 카드는 가능하면 실제 엔티티 자체를 이동합니다. 따라서 변경 가능한 상태, 남은 사용 횟수, 다른 모드가 추가한 데이터가 위치를 바꿨다는 이유만으로 사라지지 않습니다.

목적지 트랜잭션이 확정되기 전까지 원본은 유지됩니다. 잘못되거나 알 수 없는 드롭 대상은 원본을 삭제하지 않고 작업을 취소합니다. 한 번의 마우스 릴리스에서 최대 한 개의 작업만 커밋됩니다.

카탈로그 카드는 템플릿이므로 드래그해도 소모되지 않습니다.

## Always Cast

Always Cast는 전용 영역을 가집니다. 일반 슬롯과의 승격, 복귀, 교환은 일반 슬롯의 유효 용량을 고려해 잘못된 완드 구조를 만들지 않습니다.

## Undo / Redo

완드 내부 변경은 제한된 **UNDO / REDO** 기록을 가집니다.

실제 엔티티를 월드나 다른 인벤토리로 전달한 작업은 완드 snapshot만으로 항상 안전하게 되돌릴 수 없습니다. 따라서 이런 외부 handoff는 항상 취소 가능하다고 보장하지 않습니다.

# 완드

완드 작업 영역에서는 플레이어가 현재 들고 있는 완드를 편집합니다.

지원하는 수치:

- 용량 / 슬롯
- 한 번에 시전하는 주문 수
- 재충전 시간
- 시전 지연
- 분산
- 투사체 속도 배수
- 최대 마나
- 마나 충전 속도
- 반동 회복
- 완드 레벨
- shuffle
- no-reload 동작

외형 및 관련 메타데이터도 편집할 수 있습니다.

- 표시 이름
- 완드 및 카드 잠금
- sprite 경로
- sprite 오프셋
- 발사 위치

데이터가 있으면 시각적 외형 카탈로그는 완드 XML 정의를 따릅니다.

## 완드 프리셋

완드를 이름 있는 영구 프리셋으로 저장하고 다른 월드나 이후 Noita 세션에서 재사용할 수 있습니다.

프리셋은 다음을 저장할 수 있습니다.

- 완드 스탯
- 마나 값
- 시각 메타데이터
- 일반 주문 카드
- Always Cast 카드
- 슬롯 위치
- 남은 사용 횟수
- 카드의 frozen 상태

각 프리셋에는 두 가지 별도 동작이 있습니다.

- **APPLY** — 저장된 blueprint를 현재 들고 있는 완드에 적용
- **GET COPY** — 같은 blueprint로 새 완드 생성

빠른 인벤토리에 빈 완드 슬롯이 있으면 복사본을 그곳에 넣습니다. 적절한 슬롯이 없으면 완성된 완드를 플레이어 근처 월드에 둡니다.

완드 교체와 프리셋 불러오기는 commit/rollback 경로를 사용합니다. 구성이나 배치에 실패하면 고장 난 반쪽 완드를 남기기보다 불완전한 엔티티 트리를 제거하려고 시도합니다.

# 아이템과 액체

## 아이템

카탈로그 항목을 짧게 **LMB** 클릭하면 지원되는 아이템 하나를 플레이어 근처에 생성합니다.

**RMB**는 적절한 인벤토리 영역으로 전달을 시도합니다.

카탈로그 항목을 다음 위치로 드래그할 수도 있습니다.

- 호환되는 빠른 인벤토리 대상
- 메뉴 밖의 정확한 월드 위치

메뉴 안에서 유효한 대상 없이 놓으면 취소됩니다. 카탈로그 카드는 템플릿이므로 그대로 남습니다.

MCM은 Noita 빠른 인벤토리의 완드 슬롯과 아이템 슬롯 구분을 존중합니다. XML 로드, 액체 채우기, 인벤토리 전달 또는 선택적 multiplayer handoff에 실패하면 새 엔티티를 가능한 경우 제거합니다.

일부 실제 인벤토리 아이템은 게임의 생물 계열 디렉터리에 위치합니다. MCM은 폴더 이름만 보고 아이템/생물을 판단하지 않고 알려진 동작을 기준으로 분류합니다.

## 액체

액체 항목은 장식용 UI 오브젝트가 아니라 실제 내용물이 든 Noita 컨테이너를 생성합니다.

컨테이너는 들고 다니거나, 떨어뜨리거나, 깨뜨리거나, 내용물을 쏟을 수 있으며 액체는 정상 재료 반응에 참여합니다.

# 재료

Materials 섹션은 Noita의 실제 재료 레지스트리를 이용하는 월드 페인팅 도구입니다.

카탈로그는 engine에 등록된 액체, 모래 / 가루, 기체, 불, 고체 및 관련 정적/효과 재료에서 구성됩니다. 다른 활성 모드가 올바르게 등록한 재료도 자동으로 나타날 수 있습니다.

재료 발견과 비용이 큰 검증은 한 UI 프레임에서 전체 카탈로그를 처리하지 않고 제한된 작업으로 나눠 수행됩니다.

## 재료 표시

액체는 아이템 섹션과 동일한 내용물 용기 표시를 사용합니다.

비액체 재료는 `materials.xml`에 정의된 텍스처와 tint를 우선하며 상속된 정의도 포함합니다. 정의된 텍스처가 없을 때만 임의의 preview 색이 아니라 engine의 실제 재료 색을 fallback으로 사용합니다.

## 페인팅

1. 재료를 선택합니다.
2. 브러시 크기를 선택합니다.
3. 페인팅 모드를 켭니다.
4. 인벤토리를 닫습니다.
5. 월드에서 설정된 그리기 입력을 누르고 있습니다.

인벤토리를 다시 열면 활성 페인팅 모드가 종료됩니다.

페인팅은 장식용 파티클만 뿌리는 기능이 아닙니다. MCM은 engine에 맞는 방식으로 실제 cell을 월드에 배치합니다. 동적 재료는 이후에도 Noita 시뮬레이션을 따릅니다. 액체는 흐르고, 가루는 떨어지고, 기체는 이동하고, 불은 반응하며, 불안정 재료는 반응으로 변환될 수 있습니다.

재료 클래스마다 다른 배치 방식이 필요합니다. Standalone 빌드는 NoitaPatcher의 직접 월드 그리드 접근을 사용할 수 있고, Noita가 특정 텍스처 좌표에서 정의 재료의 직접 생성을 거부하는 경우 작은 PixelScene fallback을 사용합니다.

작업 큐에는 상한이 있어 큰 브러시를 오래 누른다고 한 프레임에 무제한 작업을 수행하지 않습니다.

# 퍽

## 퍽 생성과 획득

**LMB**는 선택한 퍽의 일반 pickup을 월드에 생성합니다.

획득 동작은 한 개씩 또는 일괄로 퍽을 부여할 수 있습니다. 일괄 처리는 한 UI 프레임에 모두 적용하지 않고 제한된 job으로 나눠 처리합니다.

인터페이스는 진행 상태를 표시하며, 아직 처리되지 않은 작업은 취소할 수 있습니다. 취소 전에 이미 커밋된 퍽은 그대로 남습니다.

각 복사본은 최종 상태를 직접 위조하지 않고 정상적인 퍽 적용 경로를 거칩니다.

## 퍽 제거

퍽 제거는 부여보다 훨씬 복잡합니다. 퍽은 globals, 컴포넌트, 엔티티, 플레이어 스탯, 장기 메커니즘을 바꿀 수 있으며 Noita에는 범용 역연산이 없습니다.

따라서 MCM은 충분히 안전하게 추적 가능한 역처리가 있는 상태만 제거합니다. 트랜잭션 journal은 해당 퍽 적용이 소유한 상태만 제거하고 관계없는 플레이어 상태를 초기화하지 않도록 시도합니다.

정리가 일부만 되거나 완전히 끝났다고 증명할 수 없으면 성공으로 숨기지 않고 미완료 상태로 남깁니다.

서드파티 퍽은 부여할 수 있어도 올바르게 제거할 수 있다고 보장하지 않습니다.

# 효과

Effects 섹션은 지원되는 재료 상태와 GameEffect 엔티티를 적용하고 제거합니다.

가능한 경우 상태 소유권을 고려합니다. MCM은 퍽, 게임 자체, 다른 시스템에 속한 비슷한 숨은 효과를 무차별 삭제하지 않습니다.

MCM이 만든 지속 효과는 제한된 정리 / 만료 처리를 사용해 MCM 효과 하나를 제거할 때 관계없는 상태까지 초기화하지 않습니다.

# 생물

생물 카탈로그는 정확한 XML 경로를 유지하며 이름이 비슷하다는 이유로 여러 엔티티를 합치지 않습니다.

지원 동작:

- **LMB** — 선택한 정의 엔티티를 플레이어 근처에 생성
- 메뉴 밖으로 드래그 — 확인된 월드 커서 위치에 생성
- **RMB** — 현재 플레이어를 지원되는 폼으로 변신
- 특수 **PLAYER** 항목 — 아래 설명대로 플레이어 관련 상태 생성 또는 복구

드래그한 카드를 메뉴 위에 다시 놓으면 월드 생성은 취소됩니다.

위험하거나 특수한 변신 대상의 호환 규칙은 정확한 경로를 기준으로 합니다. 파일명에 익숙한 단어가 들어 있다고 다른 폼과 자동으로 같은 것으로 취급하지 않습니다.

# 변신과 인간 형태 복귀

플레이 가능한 폼은 가능한 범위에서 유용한 네이티브 이동, 공격, 외형, 물리 동작을 유지합니다. 플레이어 입력과 직접 경쟁하는 컴포넌트는 플레이어가 해당 폼을 조종하는 동안 비활성화되거나 조정될 수 있습니다.

일부 복잡한 생물은 추가 호환 로직이 필요합니다. Boss, 스크립트 wrapper, 물리 의존도가 높은 엔티티는 플레이어 폼으로 사용할 때 원래 AI 버전과 완전히 동일하게 동작한다고 보장하지 않습니다.

복귀 동작 — 기본 **TAB** — 은 먼저 정상적인 변신 종료 경로를 사용합니다. 충분하지 않으면 standalone 빌드가 NoitaPatcher 기반 추가 복구 경로를 사용합니다.

지원되는 치명 피해 상황에서 MCM은 다음을 시도합니다.

- 적절한 경우 죽은 임시 폼이나 시체를 월드에 남김
- 인간 플레이어 엔티티 복원
- authority와 조작권 반환
- 인벤토리 보존
- 관련 플레이어 상태 복원

이는 복구 로직이지 절대적인 불사 기능이 아닙니다. 서드파티 kill script, 호환되지 않는 engine 상태 또는 프로세스 크래시는 지원 handoff를 우회할 수 있습니다.

# 빙의

빙의는 카탈로그에서 폼을 고르는 대신 이미 월드에 존재하는 생물을 직접 조종합니다.

기본 입력은 **G**입니다.

적절한 생물을 가리키고 빙의 동작을 사용합니다. MCM은 대상을 검증하고 호환되는 전환을 준비하며, 새 플레이어 제어 상태가 확인된 뒤에만 기존 월드 엔티티를 제거하거나 retirement 처리합니다.

전환이 실패하면 원래 생물이 그냥 사라지지 않도록 합니다.

빙의는 MCM 내장 카탈로그에만 제한되지 않습니다. 다른 모드가 만든 호환 생물도 동작할 수 있지만 모든 서드파티 엔티티와의 호환성을 보장하지는 않습니다.

# Player 항목

**PLAYER**는 생물 카탈로그의 특수 항목이며 일반 polymorph 대상이 아닙니다.

Spawn 동작은 별도의 플레이어형 캐릭터를 만들고 가능한 플레이어 외형 및 최대 체력 정보를 복사하려고 합니다.

이미 인간인 플레이어에게 **PLAYER** 변신 동작을 사용해도 복제본으로 변하지 않습니다. 현재 다른 폼이라면 인간 형태로 돌아가는 동작으로 사용됩니다.

# 싱글플레이 Game Over 복구

Standalone 싱글플레이 빌드는 Noita 기본 Game Over 화면에 추가 복구 경로를 제공합니다.

네이티브 연동이 필요한 게임 구조를 안전하게 식별할 수 있으면 MCM은 Game Over UI에 **“I didn't die”** 동작을 추가합니다.

게임 중 MCM은 플레이어 상태의 롤링 백업을 유지합니다. 복구 동작은 UI 클릭 handler에서 플레이어 전체를 바로 재구성하지 않고 MCM의 정상 업데이트 경로로 복구 요청을 보냅니다.

지원되는 복구는 다음을 시도합니다.

- 살아 있는 플레이어 엔티티 복원 또는 획득
- 해당 엔티티를 다시 authoritative 상태로 설정
- engine Game Over 상태 해제
- 조작권과 사용 가능한 플레이어 상태 복원
- Game Over 오디오, 음악, UI 상태를 가능한 범위에서 정리
- 복구 직후 짧은 보호 시간 제공

네이티브 helper는 fail-closed 방식으로 설계되었습니다. 하나의 주소에 영구적으로 쓰지 않고 실행 중인 지원 Noita executable에서 알려진 구조를 찾습니다. 게임 업데이트 뒤 예상 구조를 안전하게 식별할 수 없으면 불확실한 위치에 쓰는 대신 선택적 복구 기능을 사용하지 않습니다.

# 날씨와 시간

MCM은 현재 구현이 제공하는 preset 및 개별 파라미터를 포함해 지원되는 날씨와 시간 상태를 제어할 수 있습니다.

강제로 설정한 상태는 나중에 게임의 정상 제어로 돌려줄 수 있습니다. 예를 들어 특정 시간을 고정한 뒤 MCM이 해당 설정을 놓으면 Noita의 자연 시간 흐름이 다시 진행됩니다.

날씨 변경은 일회성 콘솔 명령이 아니라 제어되는 상태로 취급됩니다.

# 월드 규칙

**RULES** 섹션은 지원되는 전역 게임 동작을 변경합니다.

예시:

- 생물 관계
- 골드 동작
- 주문 사용
- fog of war
- 일부 처치 보상
- 회복 드롭
- 혈액 관련 동작
- 중력
- 물리 동작
- 발차기 힘
- 물리 조인트
- 낮밤 주기
- 기타 지원 전역 파라미터

핵심 설계 목표는 되돌릴 수 있다는 것입니다.

지원되는 규칙은 원래 상태를 기록하거나 유도해 나중에 복원할 수 있게 합니다. 배수형 컨트롤은 이미 수정된 값에 계속 곱하지 않고 원래 값을 기준으로 계산합니다.

많은 엔티티나 물리 오브젝트를 처리해야 하는 규칙은 한 번의 메뉴 클릭으로 월드 전체를 동기적으로 다시 쓰지 않고 제한된 업데이트 작업을 여러 프레임에 나눕니다.

# 순간이동

순간이동 섹션은 메인 경로, Holy Mountains, 주요 사이드 지역 및 기타 지원 지점 등 준비된 월드 목적지를 제공합니다.

플레이어를 이동하기 전에 MCM은 목적지 주변 로드를 요청하고, 플레이어를 고체 지형 안에 직접 넣는 대신 주변의 사용 가능한 빈 공간을 찾습니다.

순간이동은 여전히 월드가 실제로 로드되고 유효 위치를 제공할 수 있어야 합니다. 크게 변경된 월드에서는 fallback 동작이 필요할 수 있습니다.

# Entangled Worlds

**Entangled Worlds / Noita Proxy는 선택 사항입니다.** EW 없이도 MCM은 작동합니다.

EW가 있으면 MCM은 추가 multiplayer-aware 동작을 활성화합니다. MCM 고유 동기화 상태를 사용하는 경우 모든 peer가 호환되는 MCM 빌드를 사용하는 것이 좋습니다.

## Authority와 폼

변신 플레이어가 실수로 두 번째 네트워크 authority를 남기지 않도록 플레이어 폼은 특별한 ownership 처리가 필요합니다.

지원되는 범위에서 MCM은 EW와 폼 ownership, retirement, 인간 형태 복귀를 조정합니다. Boss 및 Kolmi 계열 엔티티에는 중복 authority와 오래된 네트워크 제어 복사본을 막기 위한 추가 lifecycle 처리가 있습니다.

MCM-owned 폼 상태로 인식되지 않은 엔티티는 EW의 일반 사망 경로가 계속 담당합니다.

## 아이템, 완드, 주문

가능한 경우 MCM은 별도 전송 시스템을 만들지 않고 EW의 정상 item / inventory 메커니즘을 사용합니다.

커밋된 완드 및 주문 인벤토리 변경은 연동이 있을 때 적절한 multiplayer refresh를 요청합니다. MCM이 만든 월드 아이템은 EW의 표준 world-item 경로에 넘길 수 있습니다.

## 퍽

일반 퍽 pickup은 EW의 표준 world-item 동기화를 사용할 수 있습니다. MCM의 퍽 상태 처리는 refresh와 제한된 작업을 조정해 일괄 작업이 복사본마다 비싼 전역 갱신을 수행하지 않도록 합니다.

## 재료

재료 페인팅은 월드 cell 변경이며 일반 item entity가 아니므로 전용 호환 경로가 있습니다.

MCM은 페인팅 작업량을 제한하고 chunk 경계에서 작업을 분리하며, 동기화 변환 작업을 내보내기 전에 EW가 요구하는 world-frame / persistence 단계를 조정합니다. 아직 로드되지 않은 streaming edge chunk는 현재 스트로크 전체를 막지 않고 뒤로 미뤄집니다.

목표는 근처 EW peer가 MCM의 일반 UI 동작을 filename-only PixelScene 호출로 원격 재생하지 않아도 지원되는 페인팅 월드 상태를 볼 수 있게 하는 것입니다.

다만 EW의 material id 가정은 그대로 적용됩니다. 수신 측에 없는 재료나 engine 재료 레지스트리가 호환되지 않는 재료는 올바르게 생성할 수 없습니다.

## 날씨, 빙의와 월드 상태

지원되는 MCM 멀티플레이 상태에는 날씨, 빙의, 일부 월드 규칙 / lifecycle 동작의 조정도 포함됩니다. Authority 체크는 두 peer가 같은 상태를 동시에 소유하려는 상황을 막습니다.

EW 지원은 의도적으로 보수적입니다. 안전한 동기화 경로를 증명할 수 없으면 모든 싱글플레이 작업이 멀티플레이에서도 자동으로 안전한 것처럼 처리하지 않고 올바른 로컬 동작을 우선합니다.

# 호환성과 제한

Noita의 많은 시스템은 느슨하게 연결된 엔티티, XML, Lua 컴포넌트 및 네이티브 engine 동작으로 구성됩니다. 따라서 MCM은 모든 수정 엔티티나 미래 게임 업데이트와의 완전한 호환을 보장할 수 없습니다.

중요한 제한:

- Spawn 가능한 생물이 안전한 플레이어 폼이라는 뜻은 아닙니다.
- 부여 가능한 퍽에 항상 신뢰할 수 있는 역처리가 있는 것은 아닙니다.
- 외부로 넘긴 주문/아이템은 내부 snapshot에서 항상 Undo할 수 없습니다.
- 서드파티 스크립트는 지원되는 사망/복구 경로를 우회할 수 있습니다.
- 네이티브 복구는 지원되는 Noita executable 동작에 의존하며 필요한 구조를 식별할 수 없으면 fail-closed 합니다.
- Entangled Worlds는 수신 게임의 레지스트리에 없는 재료를 동기화할 수 없습니다.
- 크게 변경된 인벤토리, 엔티티, 월드 규칙은 특정 모드에 맞춘 호환 처리가 필요할 수 있습니다.

MCM은 원래 상태 보존과 실패한 변경 rollback을 우선하지만, 실시간 게임 상태를 수정하는 샌드박스 도구가 모든 서드파티 모드 조합을 완전히 트랜잭션 방식으로 만들 수는 없습니다.

# 저장 데이터

MCM은 실행 사이에 유지되어야 하는 사용자 상태를 저장합니다. 지원되는 설정, 키 바인딩, 메뉴 레이아웃, 완드 프리셋 등이 포함됩니다.

모드 ID는 안정적으로 유지되므로 정상 업데이트에서 지원되는 저장 데이터를 계속 사용할 수 있습니다. 다만 새 standalone 빌드를 설치할 때는 모드 폴더 전체 교체를 권장합니다. 신구 파일을 합치면 오래된 runtime 파일이 남을 수 있습니다.

# 문제 해결

## 모드가 보이지 않음

경로가 다음으로 끝나는지 확인하세요.

`mods/metamorph_creative_menu/mod.xml`

`metamorph_creative_menu` 위에 추가 압축 폴더가 있으면 Noita가 모드를 올바르게 인식하지 못합니다.

## 네이티브 기능이나 재료 기능이 작동하지 않음

**Unsafe Mods**가 허용되어 있고 Workshop 파일과 섞이지 않은 GitHub standalone 빌드를 설치했는지 확인하세요.

## 메뉴를 열면 게임 동작도 함께 실행됨

사용자 지정 바인딩 충돌을 확인하세요. MCM은 중복을 표시하지만 원하면 그대로 둘 수 있습니다.

## 특정 생물로 안전하게 변신할 수 없음

Spawn 가능한 모든 XML 엔티티가 지원되는 플레이어 폼은 아닙니다. 특별 처리가 필요한 생물은 정확한 경로 기반 규칙을 사용합니다.

## 퍽을 제거할 수 없음

제거는 MCM이 추적 상태에 대해 지원되는 역연산을 가진 경우에만 제공됩니다. 이는 의도된 제한입니다. 추측식 정리는 관계없는 플레이어 상태를 손상시킬 수 있습니다.

## 멀티플레이에서 peer마다 동작이 다름

모든 참가자가 호환되는 MCM 빌드를 사용하고 Noita / Entangled Worlds 환경도 호환되도록 유지하세요. MCM은 호환되지 않는 재료 레지스트리나 다른 모드의 임의 네트워크 변경을 수정할 수 없습니다.

# 버그 제보

유용한 제보에는 다음을 포함하세요.

- 무엇을 하려 했는지
- 정확한 MCM 섹션과 동작
- 문제가 single-player, Entangled Worlds, 또는 둘 다에서 발생하는지
- standalone / Workshop 중 어떤 빌드인지
- 다른 gameplay 모드가 활성화되어 있는지
- 안정적인 재현 단계
- 가능하면 관련 Noita / EW 로그

변신, 빙의, 아이템 또는 재료 문제라면 가능한 경우 정확한 엔티티나 재료를 적어 주세요. 번역된 표시 이름보다 기술 ID가 더 유용한 경우가 많습니다.

# 저장소와 개발 소스

이 저장소는 플레이어가 받는 축소 아카이브가 아니라 **전체 개발 트리**를 의도적으로 보존합니다.

`metamorph_creative_menu/`에는 runtime 코드와 함께 다음이 있습니다.

- 자동 테스트
- QA 도구
- 진단 코드
- 네이티브 소스
- 빌드 도구
- release cleanup 규칙
- 개발 문서

개발과 회귀 테스트에 필요한 파일들이므로 GitHub source에 남습니다. 플레이어 설치용 ZIP은 별도로 만들어지고 development-only 콘텐츠를 제외합니다.

플레이어 패키지는 release 전용 정리도 적용받아 최소한의 player `README.txt`가 생성되며, source tree에는 개발 문서가 유지됩니다.

# 테스트

자동 테스트는 `metamorph_creative_menu/tests/`에 있으며 Python contract 검사와 Lua mock 테스트를 함께 사용합니다.

Release workflow는 저장소 루트에서 전체 imported source를 대상으로 테스트를 실행하고 통과한 뒤 player build를 배포합니다. Lua mock 부분에는 `texlua`가 필요합니다.

Source hygiene 검사는 production-facing 파일과 문서에 개발 이력 찌꺼기, 오래된 debug surface, 우발적 프로세스 산출물이 다시 들어오는 것도 막습니다.

# Source 아카이브 import와 release 과정

전체 개발 source는 `Metamorph-Creative-Menu-v...zip` 계열 아카이브에서 import할 수 있습니다.

Import workflow는 아카이브 구조를 확인하고 전체 개발 구성요소를 요구하며 source hygiene과 회귀 테스트를 실행한 뒤 imported tree를 commit합니다.

ModWorkshop / player-style 아카이브는 개발 source로 취급하지 않습니다.

공개 `latest-build` release는 전체 source에서 별도 player-builder로 생성됩니다. Builder는 QA, 테스트, 진단, 네이티브 소스 및 기타 development-only payload를 제거하고 release cleanup 규칙을 적용한 뒤 결과 아카이브를 검증하고 마지막으로 안정 다운로드 asset을 갱신합니다.

이 분리를 통해 저장소는 개발에 필요한 전체 상태를 유지하면서도 일반 플레이어 다운로드는 작고 개발 instrumentation 없이 유지됩니다.
